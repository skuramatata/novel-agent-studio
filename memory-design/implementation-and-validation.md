# 逐章生成与记忆菜单：实现记录

日期：2026-09-08。此记录描述首版实际能力；完整设计中的自动多章队列、候选分支、通用事件图谱尚未实现。

## 已接入应用的链路

- `electron/main.mjs` 的生成入口调用新的 `runtime/chapter-agent.mjs`。讨论和规划保留旧流程，正文进入单章流程；没有接入 my-pi-agent 运行时。
- `runtime/checkpoint.mjs` 按作品目录保存章节任务、场景产物、模型调用结果和恢复状态。新建任务前归档旧任务，恢复核对作品基础内容及模型。
- `runtime/memory-schema.mjs` 与 `runtime/memory.mjs` 提供正文记忆抽取、原文引用验证、来源哈希、此前章节依赖校验、按需材料选择和上下文预算。
- 新章节候选包含本章记忆，采纳时与正文在同一次 ProjectStore 保存中落盘。旧作品可以单独整理已采纳正文的记忆。
- “故事记忆”展示摘要、事件、人物/物件状态、知情、故事线与伏笔，支持筛选、搜索、原文展开和过期提示。
- “章节阅读”增加单章生成/修订、字数设置、要求输入、候选查看与采纳、恢复和整章草稿查看。

## 恢复与生成边界

每章内部约每1200字规划一个场景，按场景保存；场景篇幅允许浮动，整章按目标字数校验。输出触顶时保留返回的文本并有限续写；已完成但篇幅不符的场景做整体篇幅修订，不在结尾机械追加。

当前章内传递此前完成场景的完整正文，跨章只取最近正文和相关记忆。回忆需要明确来源章节，取回该章原文；无法定位、引用未来或未写章节时拒绝编造。审稿通过段落编号回填证据。

每次模型请求仍是非流式；没有接收到的网络响应无法恢复为文本，只能重新请求未完成片段。可以恢复已落盘片段。自动恢复不更换模型，不改写正式作品。

多章请求本轮仅交付首章并告知剩余范围；作者采纳后在章节页继续下一章。不是自动连续写完100章。

## 带证据审稿与段落补丁

- `runtime/paragraph-review.mjs` 将问题分为矛盾、缺少前情、指代疑点和普通建议。段落/句子地址由程序回填引用原文；同段矛盾需不同句子的证据，摘要不能当作原文事实。
- 自动修订前明确应保留的出处；无法裁决的关键事实停止自动修订。删除无出处断言时禁止补写过去对白或事件。指代疑点默认不强制改稿。
- 补丁按原文哈希和问题段落验证，其他段落及原有分隔符不重排。复核检查问题是否解决、既有事实、无依据新增及前后文；未通过的补丁不进入当前草稿。审稿后禁止整体篇幅重写。
- 提交链和最新草稿在同一检查点保存；恢复回放并核对哈希，避免重复补丁。通过最终审稿后才抽取候选记忆，采纳后才更新正式作品。
- 旧工作流检查点先归档，保留已生成场景；最新旧问题中仍能精确匹配原文的项作为待复核清单。必须逐项确认、驳回或保留疑点，给出新证据，不能直接继承旧结论或忽略旧问题。
- 自动化63项通过，新增覆盖不同句子证据、检索范围、段落外字节保留、过期补丁拒绝、复核否决、取消、恢复链、旧检查点迁移和旧问题逐项复核。

真实评测分两次隔离运行：`verification/paragraph-patch-live/` 是第一轮试验，暴露重审遗漏旧问题后已增加逐项复核；最终流程使用 `verification/paragraph-patch-targeted/`，从原0.1.11草稿恢复，原始试验目录不变。最终实际结果见该目录的报告。

# 连续性处理闭环验证

版本：0.1.20+20260908.172235.920.33ef7bc37097

## 已实现

审稿需要确认→独立原文裁决→有依据时自动最小修订→独立复核→最终审稿→候选记忆。无法裁决、达到修订次数限制、补丁反复无效时暂停为awaiting_input，主进程正常返回，不弹失败通知。

跨页面问题面板展示引用与处理方式，可选择保留依据、删除无出处断言或自定义说明。作者选择绑定任务ID、问题ID和原文版本；恢复核对作品基础及原供应商。选择后只修改明确相关段落，再复核；不能绕过复核直接采纳。关闭应用保留待处理状态，作品变化后旧选择失效。

任务状态持久化在检查点，面板仅持有未提交的选择和说明，不加载全书记忆；候选与正式作品仍隔离。

## 边界
