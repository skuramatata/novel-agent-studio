## 保持不变的产品要求

React Flow 展示小说事件及其前因后果，模型与作者使用同一套事件、关系、原文证据和问题数据。时间相邻、同一人物、共享引文均不自动证明因果或同一事件身份。

正式历史、未采纳候选、未来章纲必须分开。正常新事件可作为起点；悬念、传闻、人物信念、谎言和倒叙不能一律判错。预览和放弃候选不得写入正式图或正文。

系统展示原文、问题和修订建议；作者决定是否改稿。建图、检查、保留、驳回、裁定均不得改正文。作者显式发起修订后进入既有草稿流程，只有采纳才更新正式正文。

本阶段禁止的是验收时发起真实供应商付费调用，**不表示产品只能支持 mock**。正常桌面入口必须接入项目既有模型适配器；测试替身在主进程的适配接缝注入，不把函数放进 IPC 参数，不让用户注入测试函数才能使用功能。

1. **已有作品建图与跨章生成。** 两章已采纳正文、无图 → 打开事件页读取状态 → 点击建图 → 显示实际覆盖/失败 → 生成空白新章候选 → 验证实际模型请求携带历史事件 ID 和原文 → 候选预览可见跨章边、问题及原文 → 放弃一份候选并重新读取正式文件确认未污染 → 再生成、预览并采纳 → 重启同一隔离库 → 节点、边、问题和 ID 均保留。
