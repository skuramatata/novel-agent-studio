# 作者指导与自动修订

## 已确认的产品规则

模型有自动改稿权。没有明确事实取舍时，按既有事实与因果、人物、章节意图与伏笔、最小连带改动选择更符合文章的方案；关联段落一起修改和复核。作者裁定与已采纳事实优先，模型自己的修改不成为永久作者裁定。

自动修订每回合最多尝试两轮，失败尝试也占额度。自动恢复、网络重连、分批模型请求不会增加额度。作者输入、选择、手动修改、主动继续或重新生成开启新回合，额度重置；同一操作的重发必须幂等。草稿、历史版本、裁定和诊断继续保留。

结束后进入草稿工作区：查看正文和问题、提交修改要求、修订所选问题、保留原文、按段落/场景/整章重生成、手动编辑、版本比较与恢复、交付待采纳候选。未通过复核的模型补丁不覆盖当前草稿。正式作品仍通过候选采纳更新。

## 实现边界与验收

检查点拥有额度、作者操作回执和草稿版本。桌面 IPC 核对任务、作品版本与草稿指纹，防止过期操作或其他作品的操作写入。React 工作室状态负责副作用；共享草稿组件负责本地选区、输入和展示，不另建全局状态。

验收覆盖：自动尝试耗尽后仍可查看和交付草稿；自动恢复不重置、每种作者介入重置、重复请求不重置；待采纳候选可继续修改；段落/场景范围外文字保持不变；错误补丁保留诊断并可回退；既有作者裁定跨操作继续生效；真实 Electron 中完成作者指令、重生成和恢复的交互。

回滚代码不删除正式作品。新增状态为检查点可选字段，原草稿和旧版本保留；新操作前保存草稿与旧审稿会话，以便回查。

## 使用方式

创作对话默认将新输入用于当前可指导的草稿，可以直接说“继续改”“把第2场第3段写得克制一点”“重新生成第二场”。重新生成必须指定段落、场景或整章，也可以从草稿工作区选择范围。要启动另一项规划或章节任务，切换输入框上方的“这条要求用于”。

工作区提供问题多选、保留原文、修改要求、范围选择、手动编辑、版本对比与恢复，以及“交付当前稿”。有同任务的待采纳候选时仍能继续修改，旧候选保留为历史；已有另一任务候选时先处理该候选。局部修改通过后只读复审，其他问题保留给作者决定是否扩大范围。原文已变化的旧发现留在审稿记录，不混入当前待处理列表。

勾选问题后，主按钮直接显示“自动修改所选 N 项问题”；填写要求后显示“按要求修改”。此前模糊作者要求产生的待答条目标为“需补充要求”，点击会聚焦输入框；补充具体改法或选择保留原文后继续。选择问题时隐藏通用继续按钮，避免所选问题没有传入请求。按钮标题不再作为作者指令写进审稿上下文。

工作区就地显示运行进度、停止入口及操作结果，正文没有变化会明确说明。待回答、重试或失败不算完成，保留输入和勾选；草稿操作不再把视图自动滚离当前控件。所选历史版本与当前正文相同时显示“已是当前草稿”；恢复不同版本会更新当前正文并显示结果。已有相同正文的待采纳候选时不能重复交付，可用“查看待采纳候选”定位聊天或阅读页的采纳入口。

主动开启新一轮审稿、核对或修订不能使用上一作者回合的成功结论；同回合恢复继续复用已成功步骤，保留原有幂等与失败恢复机制。

自动处理结束不等于作品已经采纳，也不等于文学质量认证。作者可以交付仍有建议的版本，摘要明确说明检查状态。采纳后如需继续修改正式章节，在章节阅读页创建本章修订候选。草稿修订不会复用该章旧正文的记忆索引；采纳后可重新整理记忆。
