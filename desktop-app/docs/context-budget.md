# 分阶段上下文预算

当前预算口径与原文去重已更新，见 [Token预算与原文去重](token-budget-and-source-deduplication.md)。下面的触发问题保留旧版现场。

## 触发问题

第五章已写完第一场景，但生成第二场景前触发本地 60,000 的保守预算限制。此前按人物或物件命中选择整个历史记忆片段，前四章 120 条记录几乎全部进入每个写作请求，随后不断叠加本章已写正文。旧日志在预算检查后才更新阶段，因此错误还显示在已完成的第一场景。

## 写作材料

`context-budget.mjs` 对实际发送的写作消息按记录选择历史材料。最近一章与明确引用章节的记录、明确引用全文、前章末尾、本章已写正文、当前草稿及相关后文完整保留；其余记录依据当前场景行动、物件、知情需求和章纲排序。全书常见人名降低权重，不再因为一个名字命中而整份灌入。

选择基于最终消息（含系统指令、输出预留和格式纠错历史），为历史证据设置 10,000 本地 BPE 估算 Token 的软额度（旧字符估算口径为 22,000），同时保持原 60,000 的应用上限。必需材料可占用软额度之外的空间；真正无法容纳时仍明确失败，报告输入估算、输出预算和上限。

这是请求投影，不修改作品的原始记忆、已写草稿或审稿上下文。入选记录的逐字引文、知情人、陈述性质和时间信息保持对应，quoteIndex 重新映射。historyCoverage 提供每个历史片段的总记录数及本次入选原索引，提示模型不得将未入选推断为全书不存在。检查点的 contextSelections 与创作日志保存实际选取范围和估算。

## 审稿材料

审稿继续使用原有完整来源。`review-payload.mjs` 统一文档表示为 `paragraphs: [[段号, 第1句原文, 第2句原文, ...]]`，删除重复 JSON 字段和显式句号包装。句子在行中的位置即原句号，所有句子、来源 ID 和段号不变，原始文档版本和补丁提交链不变。审稿、裁定、修订计划和复核共用此表示。

`model-budget.mjs` 集中本地 BPE 代理估算、安全余量、实际用量校准及应用上限。预算检查前更新当前执行阶段，失败不会误报到上一场景。未提高硬上限，未以摘要替换审稿证据。

## 验证

- `tests/review-payload.test.mjs`：紧凑文档逐句保持原文、编号和版本。
- `scripts/verify-repair-plan.cjs verification/context-budget-fix`：真实模型响应在隔离桌面应用重放，核对一次恢复到候选、重启及采纳。
- 真实模型进度、候选与正式数据完整性检查保存在 `verification/context-budget-fix/live/`；桌面重放不调用外部模型、不改正式作品。
