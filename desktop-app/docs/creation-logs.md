# 完整创作过程日志

入口为左侧「创作日志」，默认使用纵向「执行时间线」。步骤按开始时间从早到晚排列，点击步骤在原位置展开输入输出，可同时展开多步对照；同一步的重试集中显示。未采集时间的旧节点列于后方，保留存档顺序，不编造发生时间。

日志按当前作品隔离，可选择当前或历史任务，并按阶段、异常与等待状态、关键词筛选。历史任务每页 30 项。「节点流程」保留 React Flow：点击画布节点或使用“定位节点”，右侧查看详情。

“事件记录”保留原有事件列表：默认展示最新 200 条匹配结果，可继续加载更早记录。搜索覆盖所选任务全部事件；执行时间线与流程视图的搜索也覆盖已保存的节点输入、输出与错误。仅异常筛选保留曾经失败、后来重试成功的节点。

## 节点流程与输入输出

- 节点详情分别展示节点输入、最终模型请求、原始可见回答、解析结果、接收结果、校验与错误。通过尝试选择器检查每次纠错或恢复，成功不会覆盖此前失败。
- 最终请求在供应商适配器完成参数与消息处理后、发送之前落盘。原始可见回答在解析和业务校验之前落盘；流式中断保留已收到的部分回答并标注未接收。
- 结构化生成、正文及篇幅调整、讨论/规划入口都记录模型调用。本地索引、检索、上下文组装记录程序输入输出；已保存正文与规划 DAG 复用节点复用检查点证据。
- 实线表示规划 DAG 中已记录的依赖。虚线仅表示有时间记录的节点开始先后，不代表数据依赖；时间相同或历史关系缺失时不补画先后连线。
- 同一逻辑节点中的多次请求集中显示；缓存复用单独显示次数及来源，不计为新模型调用。不同输入对应的旧节点不能展示被后续输入覆盖的新结果。
- 对象、数组及能解析为对象/数组的 JSON 字符串，使用可折叠的 JSON 视图；嵌套字段中的 JSON 字符串也可展开，并标明已解析。普通字符串按实际换行展示；正文、未完成或非法 JSON 保留文本。复制全文保留原始已保存内容，不把展示转换写回记录。
- 长内容完整展示、独立滚动并支持复制全文。只有展开或选中的节点详情通过 IPC 按需传输，切换任务或作品时清空展开状态并隔离过期响应。

## 记录内容

- 任务：创作请求、模型、启动、暂停、失败、恢复、候选就绪和完成。
- 规划：模型调用与校验、规划 DAG 节点开始和完成。
- 正文：分场景调用、单次输出结束原因、耗时、供应商返回的 Token 用量、正文保存及修订字数。
- 审稿：发现问题、重开原因、作者回答与裁定、补丁复核、失败重试，以及已提交修订的段落前后对照。
- 记忆：抽取调用与结果校验；单独整理已采纳正文时记录索引写入结果。
- 候选：生成结果与任务关联；采纳、放弃与作品保存使用同一份消息状态，不额外维护可能脱节的日志状态。只有讨论回复时，不显示“采纳到作品”。

事件摘要与详细节点记录分开保存。详细记录包含本地模型请求体与业务上下文，不记录请求头、供应商密钥或模型隐藏思考；查看时隐藏常见凭据文本并标明脱敏。Token 用量为空时不编造；模型输出达到单次上限会单独显示结束原因。

## 状态与实现边界

过程事件保存在检查点的 `creationLog` 中，和检查点一起原子落盘；重复保存相同状态不会重复生成场景、节点和任务状态事件。审稿事件复用已有审稿记录，前端按时间统一展示。

候选消息新增可选 `taskId`、`createdAt`、`handledAt`，旧作品无需迁移即可读取。采纳与放弃时间在保存作品时由主进程填写。新任务归档旧检查点后，原任务日志仍可查看。

旧任务只展示检查点、已保存正文、修订提交和问答等已有证据；没有记录的时间、最终请求和逐次校验明确标注缺失。基础消息不冒充最终发送内容，原始输出不冒充接收结果。首次恢复旧任务后开始追加新记录，不把补录时间冒充历史发生时间。读取日志不写回旧任务。

`runtime/creation-log.mjs` 负责事件查询与节点详情入口；`execution-log.mjs` 负责调用/程序记录与检查点节点投影。`providers`、`structured-step`、`chapter-agent`、`agent` 与 Electron 在实际执行边界记录。`useCreationLogs` 负责读取、轮询及过期结果隔离，`CreationLogs` 负责筛选和视图切换，`ExecutionTimeline` 本地管理展开状态，`ExecutionFlow` 负责辅助画布，两者复用 `ExecutionNodeDetail` 展示详情。历史任务摘要有内存缓存，只加载所选任务的完整内容。

## 验证

`tests/execution-log.test.mjs` 验证最终请求先于网络调用保存、原文先于校验保存、纠错结果隔离、缓存复用、讨论入口、流式中断、旧记录缺失与只读历史、同名结果覆盖和程序检索失败。

`scripts/verify-execution-logs.cjs` 使用独立作品库与模拟模型，验证真实 Electron IPC、默认纵向时间线、顺序与多步展开/收起、辅助流程图点选、尝试切换、JSON 及嵌套字符串展开、普通文本与原文复制、完整内容滚动、筛选、视图切换、作品隔离、页面返回及重启历史读取。复制测试截获参数，不改系统剪贴板。结果在 `verification/execution-logs/`；设置 `NOVEL_VERIFY_EXECUTABLE` 可对打包客户端运行同一检查。

这些验证说明日志和程序链路可检查，不构成文学效果或真实供应商稳定性的评测。

`tests/creation-log.test.mjs` 覆盖事件去重、恢复持久化、凭据文本隐藏、旧时间缺失、修订对照、采纳/放弃、历史查询、全事件搜索、非法编号和损坏文件隔离。

`scripts/verify-review-workflow.cjs` 同时验证审稿恢复及日志菜单、异常筛选、归档后重启读取、作品隔离。运行时使用独立临时目录和模拟模型，不修改正式作品。界面截图与报告输出到 `verification/review-workflow/`。

交付验证：101 项自动测试通过；最终打包客户端的日志筛选、任务归档后重启查看、候选采纳记录和作品隔离均通过。只读检查现有作品可读取 8 个任务，当前旧任务还原 13 条记录，未写回原检查点。版本与包内文件一致性见 `verification/creation-logs/package-report.json`。
