# 完整创作过程日志

入口为左侧「创作日志」。按当前作品隔离，选择当前或历史任务；可按阶段、异常与等待状态、关键词筛选。默认展示最新 200 条匹配结果，按时间从早到晚排列；可继续加载更早记录。搜索在所选任务的全部事件上执行，不只搜索当前显示页。历史任务每页 30 项。

## 记录内容

- 任务：创作请求、模型、启动、暂停、失败、恢复、候选就绪和完成。
- 规划：模型调用与校验、规划 DAG 节点开始和完成。
- 正文：分场景调用、单次输出结束原因、耗时、供应商返回的 Token 用量、正文保存及修订字数。
- 审稿：发现问题、重开原因、作者回答与裁定、补丁复核、失败重试，以及已提交修订的段落前后对照。
- 记忆：抽取调用与结果校验；单独整理已采纳正文时记录索引写入结果。
- 候选：生成结果与任务关联；采纳、放弃与作品保存使用同一份消息状态，不额外维护可能脱节的日志状态。只有讨论回复时，不显示“采纳到作品”。

日志记录可观察的执行结果，不记录模型隐藏思考，也不复制请求头、密钥配置或整份模型上下文。Token 用量为空时不编造；模型输出达到单次上限会单独显示结束原因。

## 状态与实现边界

过程事件保存在检查点的 `creationLog` 中，和检查点一起原子落盘；重复保存相同状态不会重复生成场景、节点和任务状态事件。审稿事件复用已有审稿记录，前端按时间统一展示。

候选消息新增可选 `taskId`、`createdAt`、`handledAt`，旧作品无需迁移即可读取。采纳与放弃时间在保存作品时由主进程填写。新任务归档旧检查点后，原任务日志仍可查看。

旧任务只展示检查点、已保存正文、修订提交和问答等已有证据；没有记录的时间明确显示“时间未记录”。首次恢复旧任务后开始追加新事件，不把补录时间冒充历史发生时间。

`runtime/creation-log.mjs` 负责收集与查询；`checkpoint`、`chapter-agent` 和 Electron 记录实际动作；`useCreationLogs` 负责读取、轮询及过期结果隔离；`CreationLogs` 负责筛选与展示。历史任务摘要有内存缓存，只加载所选任务的完整内容。

## 验证

`tests/creation-log.test.mjs` 覆盖事件去重、恢复持久化、凭据文本隐藏、旧时间缺失、修订对照、采纳/放弃、历史查询、全事件搜索、非法编号和损坏文件隔离。

`scripts/verify-review-workflow.cjs` 同时验证审稿恢复及日志菜单、异常筛选、归档后重启读取、作品隔离。运行时使用独立临时目录和模拟模型，不修改正式作品。界面截图与报告输出到 `verification/review-workflow/`。

交付验证：101 项自动测试通过；最终打包客户端的日志筛选、任务归档后重启查看、候选采纳记录和作品隔离均通过。只读检查现有作品可读取 8 个任务，当前旧任务还原 13 条记录，未写回原检查点。版本与包内文件一致性见 `verification/creation-logs/package-report.json`。
