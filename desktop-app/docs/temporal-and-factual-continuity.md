# 时间与事实连续性校验

本次修复针对逐章生成时日期和时长漂移、物件行动主体变化、证词或文件被误当成事实，以及缺少依据的肯定推断。已有作品正文不会被后台自动改写。

## 生成与修订流程

1. 对已采纳的前章正文提取带原文出处的记忆。新记录保存行动者、动作、对象、前后状态、材料形态和时间信息。
2. 从有效记忆派生时间锚点与对象记录。时间锚点独立于一般相关性检索；同一物件兼顾最早行动和最近状态。表内只使用已采纳正文，不向写作者传递隐藏真相时间线。
3. 每个场景规划必须包含开始、距前场景间隔、持续时间、结束四项。绝对日期不明时使用相对时间，缺字段时自动纠正，不能把模型未填的字段假装补齐。
4. 章节写完后，独立扫描全部此前正文，按当前稿检索相关原文及相邻段，并优先保留初始和最近日期。这个过程不依赖写作者那一批记忆是否命中。
5. 对当前稿重新提取事实，执行时间、状态、证据三个专项检查，再做综合审稿。每项专项必须返回原文依据和判断理由；专项问题不能被综合审稿的空结果覆盖。
6. 延用现有依据裁定、最小段落补丁和独立复核。补丁后重新提取当前稿，重新计算明确的时间关系，防止旧算术结果误报新稿。
7. 候选采纳后，记忆随最终正文一起保存。原文哈希和前章依赖哈希变化时，旧索引不再有效；只有章纲的章节不会成为历史证据。

## 时间与证据边界

- 公历日期明确时，程序计算经过天数；不擅自推断农历、未知年份的闰日或跨年。第几天与已经经过几天仍需结合原文判断，程序算术只提供核对依据。
- `narration`、`testimony`、`document`、`inference`、`unknown`分别记录直接叙述、证词、文件所载、推断和未知。直接叙述也不保证叙述者可靠。
- 材料形态区分原件、誊抄件、保留原样的副本、口述和未知。文件写着某人到任，不自动证明此人实际到任。
- `unsupported_inference`单独表示把材料不能支持的判断当成已证实结论。必须同时引用实际材料和结论，先核对所有提供来源；能收回无依据断言时定向修订，关键事实无法裁决时沿用作者裁定流程，禁止补造照片、摹写或过去行动。
- 人物明确的猜测、互相冲突的证词、具有可辨认对照的档案异常，不自动判为错误。
- 专项结论有原文依据，指出材料不足影响当前结论并明确要求裁定时，即使模型把问题归为普通疑点，也必须进入现有依据裁定流程。只有未知日期、普通留白而未指出实质问题时不会因此阻断。

## 恢复与容量

新建任务带`continuityVersion: 1`，新整理的记忆使用相同版本标记。旧作品兼容读取；新任务会补齐旧记忆的连续性信息。已经在执行的旧检查点保留原来的证据地址和补丁恢复链，继续原流程；重新生成章节才启用本次专项，避免破坏未完成的作者问答与已提交补丁。

写作者的时间投影最多32条、相关对象记录最多24条，回查摘录默认最多100段、20000字符，均提供覆盖信息。程序扫描所有前章不等于模型阅读了全部前章；未命中不能断言全书不存在。当前仍采用词项检索和模型语义判断，不能保证长篇无漏检。

综合审稿和专项审稿各最多提出16项，合并后保留最多32项，后续裁定和补丁结构支持合并数量，不静默丢弃第17项以后的问题。字数扩写位于审稿之前；审稿后的修改仍受段落与版本校验约束。

## 验证入口

- 自动化：`npm test`，覆盖日期算术、闰年/未知历法边界、历史回查、时间锚点保留、过期索引、证据推断分类、合并不丢问题、补丁后重新检查，以及原有取消、恢复、作者裁定和字数流程。
- 实文样本：`node scripts/evaluate-continuity.mjs /绝对路径/守塔人-正文.md --live`。只读输入文件，在`verification/continuity-v1/live/`保留请求、响应和结果。包含到岗日期、鱼账时长、遗物摆放者、誊抄件笔迹四个问题及两个应保留的对照。
- 完整真实流程：`node scripts/verify-continuity-flow.mjs`，使用独立小型作品验证前章记忆、场景时间、真实生成、专项审稿、复核与候选；`--resume`可恢复隔离检查点。测试脚本的`--resolve`仅为这个固定隔离样本模拟作者裁定，不能用于真实作品或作为无人干预通过的证明。
- 打包检查：`npm run pack`之后运行`node scripts/verify-continuity-desktop.cjs`。使用独立用户目录启动验证实例，核对包内元信息、运行时代码和界面完整版本，不退出用户正在生成内容的进程。

真实模型样本用于验证本次错误类型，不能替代全书审读或证明文学质量。验证报告与部分失败响应保留在验证目录，最终交付结果另见同目录的验收记录。
